# Backend Quality Audit

**Date**: 2026-10-20
**Scope**: `backend/` (126 main files, 9 `*Test` + 23 `*IT`; package `com.lcs.findraco`), plus the deploy files that shape the backend (`Dockerfile`, `docker-compose.yml`, `frontend/nginx.conf`, `.github/workflows/ci.yml`).
**Method**: seven read-only lenses run in parallel, one clean context each: A API layer, B services and domain, C DTOs and error contract, D persistence, E security and config, F tests, G tooling and docs. Findings repeated across lenses are merged here; the lens IDs are kept in brackets for traceability. The High findings marked ✔ were re-checked in the code by the orchestrator. Nothing was run against a database.
**Purpose**: input for the backend standards. Each finding is reviewed with the user and becomes a fix, a rule, a refactor slice, or is dropped. Model: `frontend-quality-audit.md`.

---

## Verdict

The backend is in better shape than the frontend was, and in different places. The core is sound: thin controllers, every query plan-scoped, roles checked through `PlanAuthorization`, money in `BigDecimal` with exact cent splitting, Flyway with `ddl-auto=validate`, and a session design (hashed opaque tokens, rotation, family revocation) better than most apps this size.

The damage has two causes:

1. **Rules that live only in one place.** Invariants enforced by one write path and skipped by another (CSV import skips participants; series edit skips the validations series create runs), and rules that exist in Java but not in the database (email uniqueness, CSV dedup, column lengths). This is where the real bugs are, and two of them corrupt data in normal use.
2. **No mechanical gate, same as the frontend had.** CI runs 9 of 32 test classes; the 23 `*IT` and the JaCoCo gate never run before deploy, and they can only run by wiping the shared dev database. There is no formatter, ArchUnit or `-Xlint`. The code still follows the rules that could be checked, so adding gates now freezes a clean state cheaply.

The standards are silent on persistence, security, logging, time, testing amounts and structure, and the two backend skills describe a generic app (`Product`, `UserDetails`) and an error contract (ProblemDetail) the code does not have yet.

## A. Missing standards (root cause)

The frontend effort defined how each kind of code should work, down to architecture, wrote it into skills, then brought the code in line slice by slice. The backend has none of that layer: `CLAUDE.md` holds 10 bullets and two generic skills (`backend-endpoint` 142 lines, `backend-exceptions` 109) against five project-specific frontend skills (1,600 lines) whose every rule names its enforcement. Most findings below are symptoms of a rule that does not exist.

## Not a problem (kept as is)

- **Controllers**: thin, one service call per handler, `@Valid` everywhere, `HttpStatus.CREATED`/`noContent()` used consistently, `ApiRoutes` the single source of route literals, identity parameter last.
- **Plan isolation**: every lookup goes through `findByIdAndPlan`/`findByPlanAndSeriesId` with the plan from `PlanContext`, which checks membership and rejects soft-deleted plans; non-member → 404 (privacy), asserted in tests. IDOR spot-checks found nothing.
- **Roles**: every mutation calls `PlanAuthorization.requireXxx`; series ops check ownership per occurrence.
- **Money**: `BigDecimal`/`numeric` end to end; EQUAL split and item allocation run in integer cents with largest-remainder and deterministic ties.
- **Sessions and reset**: hashed opaque tokens, rotation with a 30 s grace, family revocation on replay (`noRollbackFor`, `PESSIMISTIC_WRITE`); HttpOnly + Secure + SameSite=Strict cookie scoped to `/auth`; reset tokens 256-bit, hashed, 60 min, single use, sign out everywhere. CSRF off is correct for this design. The 15-minute access-token window after logout is a recorded trade-off.
- **Persistence base**: Flyway + `validate`; data-preserving migrations with backfills; enums as STRING with DB CHECKs; child aggregates cascade in JPA and in the DB; plan deletion is a recorded soft delete; category delete reassigns or blocks.
- **Pure domain components** (`SplitResolver`, `ItemShareAllocator`, `SeriesRegenerator`, `CategorySpendingAssembler`): dependency-free, `Clock` seam, unit-tested, in the JaCoCo gate. The pattern to follow for the L2 split.
- **Tests that exist**: real JWTs through the production `JwtService`, no `@WithMockUser`; deny tests check for no partial write; TRUNCATE-not-rollback is deliberate (L-007) and proven; outcome-based names. The surefire `*Test` / failsafe `*IT` split and the disposable-DB name guard.
- **DTO basics**: no Lombok or MapStruct, immutable response DTOs with copied collections, `PaginatedFilterDto` (bounded page size, whitelisted sort), `@Valid` cascading into nested lists.
- **No secrets in git history** (JWT, DB, SMTP, private-key and AWS patterns checked); no actuator exposed; lean dependency set; `app.version` from the Maven version.
